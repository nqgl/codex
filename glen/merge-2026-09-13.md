# Upstream integration — September 13, 2026

This integration covers 315 upstream commits, from `93ac341410` to `6f39a47bb3`.

## Notable upstream changes

- Per-step model/settings snapshots now govern tool execution, request metadata,
  and hooks. Global instructions refresh at model-request boundaries.
- Guardian's shared reviewer moved into `codex-guardian-reviewer`.
- The TUI gained voice conversations, voice settings, better caption ordering,
  and native runtime packaging. This is separate from composer dictation.
- Agent/worktree navigation, streaming prose, paste/history search, terminal cursor
  repair, and scrollback preservation improved. The Astra sparkle animation was removed.
- Goals can be paused at the user's explicit request.
- Memory v2 adds separate extraction, consolidation, and read prompts behind
  version/dual-write configuration. Version 1 remains the default.
- Thread attachments and disabled-plugin selections are persisted. The old
  `thread/rollback` API was removed; `thread/revert` and historical rollout replay remain.
- The personality-selection UI was retired upstream. Legacy personality config
  remains a compatibility surface; the custom base-instruction file is unchanged.

## Custom integration decisions

- Preserve explicit/balanced/proactive delegation and runtime concurrency controls;
  adapt their resolution to captured step settings, keeping local policy precedence.
- Preserve queryable code-mode bundles and truncation recovery while adopting the
  new dispatch telemetry and receiving-model image-detail normalization.
- Preserve local math typesetting, raw toggle, image invalidation, and synchronized
  composer-height replay. Upstream cursor/scrollback changes are complementary.
- Preserve Live Transcribe dictation with medium delay and explicit ordered commit.
  Route notifications to the active voice/dictation owner, ignore replay as live
  microphone state, and prevent both audio modes from starting over each other.
  Remove the old blanket embedded-server override: realtime is now enabled by
  default upstream, so that override bypassed daemon trust and reconnect behavior.
  Dictation remains embedded-only. Explicit `--enable realtime_conversation`
  startup overrides select embedded mode instead of implicit daemon reuse;
  explicitly remote sessions retain their existing dictation restriction.
- Preserve monitors, directory watches, persistence, fork inheritance, agent-message
  feeds/wakeups, Reserve refusal, and older-Git worktree listing compatibility.
- Keep custom Guardian denial wording at the reviewer's new location. Retain the
  separate upstream review-failure wording and policy mechanics.
- Keep the concise goal continuation, adding explicit user-requested pause semantics.
- Accept deletion of obsolete upstream personality/sandbox commands and sparkle tests;
  retain the custom delegation/monitor controls rather than restoring removed UI wholesale.

## Prompt audit

The base override and registered memory-v1, review, orchestration, role, and
permission rewrites remain. The goal continuation and Guardian denial location
required explicit merges. The new memory-v2 templates are upstream originals,
not silently rewritten copies of the custom memory-v1 prompts. Enabling v2 later
requires a separate prompt review if the same memory-writing philosophy is desired.
The v2 text emphasizes task chronology, explicit preferences, provenance, and
deletion-aware consolidation. Its rendered read prompt includes a bounded memory
summary and can exceed 1,000 tokens: this is a **P0 manual context-review surface**
under the repository's size-review rule, not a newly enabled feature or a secret.

Upstream migration 55 renames `thread_artifacts` to `thread_attachments` and its
type column, without colliding with our separate monitor migration ledger.
A fresh private backup was taken. Applying the SQL migration to a copy preserved
all thread, monitor, and attachment row data; SQLite integrity checking passed.
The live database was opened read-only for backup, not migrated. Once the updated
binary migrates it, older binaries that query `thread_artifacts` are not compatible.

# Upstream integration — September 7, 2026

This integration preserves the math renderer, inline equations, synchronized
redraws, Reserve refusal, and earlier database fixes. It incorporates 165 upstream
commits, from `1d6727c0b5` to `93ac341410`.

## Notable upstream changes

- Guardian review now uses a shared decision path, with stronger root-authorization,
  inherited-context, stale-approval, and compaction-checkpoint handling. Legacy review
  paths were removed, and model-specific review policy support was expanded.
- Session restoration can open a conversation read-only when another process owns
  its writer. Resume and working-directory transitions run outside deep event-dispatch
  stacks. New sessions use server model defaults while respecting explicit settings.
- Managed worktrees gained CLI support, a TUI browser, and linked-worktree discovery.
- Async questions gained selectable options and inline Other answers; history and
  queue navigation were integrated with the question interface.
- GPT-6 Astra was added to the bundled and Bedrock catalogs. Bundled OpenAI-docs
  samples gained corresponding model guidance.
- Copying responses preserves Markdown; status fields can be copied individually.
  Assistant file citations and markup parsing were improved.
- Voice-host WebRTC, native audio packaging, standalone updater behavior, MCP auth
  notifications, user verification, and several sandbox/platform paths changed.
- The deprecated `codex mcp-server` command was removed upstream. MCP client/server
  connection management remains; this is the old mode that exposed Codex itself as
  an MCP server. No reference to that command was found in the active Codex config.
- Unified-exec TTY support now has a separate feature flag, enabled by default.

## Database compatibility

Upstream migration 54 conflicts with the monitor migration formerly numbered 54.
Monitor migrations now use `_codex_monitor_migrations`, leaving the standard
`_sqlx_migrations` ledger entirely upstream-compatible. Known old monitor layouts
(48/49, 51/52, and 54/55) are transferred by exact checksum in a transaction.
Other records remain subject to normal SQLx validation; the repair does not bless
an unknown checksum for a known upstream version.
The repair acquires SQLite's writer slot before reading the ledger, so concurrent
startup waits rather than failing a deferred transaction's read-to-write upgrade.

Validation on a database copy preserved all thread and monitor rows byte-for-byte
over their original columns. SQLite integrity checking passed. Backups were kept
outside the repository, and the original database was not migrated during integration.

Once the new binary opens a database, an older custom binary that still assigns
monitor migrations to upstream versions 54/55 cannot reopen it. Use updated custom
binaries consistently. A binary rollback needs a compatible database strategy;
do not overwrite newer conversation data with an older backup.

## Pre-existing discrepancy found during audit

`thread/start.multiAgentMode` was already ignored before this merge, despite the
old README claiming otherwise. The supported configuration and
`thread/settings/update` / `turn/start` controls remain. Documentation now describes
that distinction; this merge does not silently expand the start API's behavior.
